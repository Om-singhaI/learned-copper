# Learned Copper: Guiding PCB Autorouting with a Model Trained on Human Routed Boards

CS57600 Machine Learning, Fall 2026. Term Project Midway Report. Om Singhal, working alone.

## 1. Title and Team Information

The project is Learned Copper: Guiding PCB Autorouting with a Model Trained on Human Routed Boards. I am working on it alone. The code, the data scripts, the frozen splits and the result files are in the public repository github.com/Om-singhaI/learned-copper.

## 2. Updated Project Overview

Autorouters draw the copper traces on a printed circuit board, and the free ones do it badly enough that most designers still route by hand. The project asks two questions. Can a model trained on real boards that people routed learn where a net's copper belongs? And if that prediction is handed to a classical router as a cost map, does the router finish more nets with fewer design rule violations than it does alone? Both questions are posed on real boards and scored with the metrics a published benchmark already uses, so the answer can be compared with existing systems rather than stand on its own.

The direction is the same as in the proposal, with four changes that came out of the data work.

* Data source. The proposal named the open schematics collection as the primary source. After measuring it (87,931 records, about 55,000 board files, 317 GB, no splits, boards repeated across schematic sheets) I switched to the PCBench corpus of human routed KiCad boards and to the test lists published with PCBWorld, which draw on the same corpus. Open schematics is now the scale up option for the final weeks.
* Formulation. One training sample is one net rather than one board, with the copper of all other nets given as input. This is how a sequential router consumes guidance and it multiplies the data by about 27.
* Evaluation. Design rule checks run with copper zones refilled and count only copper rule types, for the reason given in the next section. The primary test set is the 97 test boards that pass this stricter check.
* Scope. Two layer boards only, which are 1,037 of the 1,157 boards in the pool. Every claim is stated for that regime.

## 3. Dataset, Data Exploration and Preprocessing

The data is the PCBench corpus of 1,157 human routed KiCad boards from 846 GitHub repositories, in the mirror that the Freerouting project distributes for research use. Each board comes with its original routed file, an unrouted twin and a ground truth count of nets, pads, tracks and vias. The test set is PCBWorld's fixed lists of 99 easy, 10 medium and 10 hard boards from the same corpus, for which the paper reports Freerouting and reinforcement learning results in the metrics this project uses. The 119 test boards and all 94 source repositories behind them are excluded from training. The lists are frozen as hash files in the repository and regenerated by a script. The boards themselves stay out of the repository because their licenses vary.

| Stage | Count |
|---|---|
| Boards in the PCBench mirror | 1,157 from 846 repositories |
| Two layer boards | 1,037 |
| Boards passing the design rule filter | 633 clean, 68 flagged, 456 rejected |
| Test boards and their repositories, excluded from training | 119 boards, 94 repositories |
| Boards rasterised so far | 645 (477 training pool, 168 held out) |
| Training samples, one per net | 17,718 |
| Owner split, train | 410 boards, 338 repositories, 12,961 samples |
| Owner split, validation | 67 boards, 60 repositories, 2,054 samples |
| Copper pixels per layer at 128 by 128 | 0.31 percent front, 0.24 percent back |

Preprocessing runs in five scripted steps. Every board is loaded with KiCad's own Python interface and inventoried; all 1,157 load and the counts agree with the ground truth file on every board. KiCad's design rule checker then runs on each board with zones refilled, and a filter keeps boards that are fully connected, have a valid outline and tracks, and show no shorts, crossings or clearance errors under their own rules (a flagged tier allows up to ten clearance findings). Geometry is extracted to JSON in millimetres: outline, pads with their layers and nets, tracks, vias and zones. Each board is rasterised to a square grid scaled to the board, 0.23 mm per pixel at the median at 256 pixels. Finally the splits are written as lists of board hashes, grouped by source repository.

Three things from the exploration are worth reporting.

* Human boards appeared to violate their own clearance rules on a large scale: 940 of 1,157 boards, thousands of findings. 96 percent of the findings involved copper zones. The cause is stale zone fills in old files, which KiCad does not refresh on load. Refilling before the check reduced a 30 board pilot from 4,304 clearance errors to 97. Any paper that checks real boards without refilling will report wrong numbers, and this is now a rule in the pipeline.
* Refilling also breaks connectivity on 69 boards, because the refreshed fill no longer reaches a pad the old one covered. Those boards are rejected. 22 of the 119 test boards fall out this way, so the 97 that survive form the primary test set and all 119 are reported with completion measured against the human reference's own connectivity.
* Copper is sparse. A net's traces cover about 0.3 percent of pixels per layer at 128 by 128, so a model that predicts nothing is already 99.7 percent accurate and plain accuracy says nothing. Every metric below is computed on copper pixels only, and the losses are chosen for the imbalance.

## 4. Methods and Initial Results

Each sample is one net on one board. The input is a six channel image: the board outline, this net's pads on the front and back copper layers, every other pad on each layer, and the copper of every other net. The target is two channels, this net's tracks and vias on the front and back layers. Three models are trained and scored on exactly the same samples and splits.

* Distance heuristic (baseline). The probability of copper decays with distance from the net's own pads, with the decay length chosen on the training set from a small grid. This is roughly what a shortest path router assumes.
* Gradient boosting (baseline). LightGBM on nine per pixel features: distance to this net's pads on each layer, to other pads on each layer, to other copper, to the net's pad bounding box, the outline flag and position. 300 rounds on 200,000 sampled pixels per layer, with the decision threshold tuned on the training boards.
* UNet (advanced). A four level encoder decoder with 2.1 million parameters, trained with binary cross entropy plus a soft Dice term for the sparse target, AdamW with a cosine schedule, and rotation and flip augmentation. Ten epochs at 128 by 128 took about four hours on the laptop GPU.

Two split protocols are compared on purpose. The random split pools all samples and divides them at random, so other nets of the same board and near duplicate boards from the same repository sit on both sides. The owner split keeps every board of a source repository on one side. Both are reported so that the inflation from leakage is measured rather than assumed. The 168 held out boards (the test boards and the other boards from their repositories that pass the filter) are never trained on under either protocol and give a third number.

| Model, 128 by 128 | Owner split validation IoU / F1 | Random split validation IoU / F1 | Held out boards IoU / F1 |
|---|---|---|---|
| Distance heuristic | 0.084 / 0.155 | 0.090 / 0.165 | 0.089 / 0.164 |
| LightGBM, tuned threshold | 0.129 / 0.228 | 0.136 / 0.240 | 0.104 / 0.188 |
| UNet, 10 epochs | 0.212 / 0.350 | running at the time of writing | 0.191 / 0.321 |

IoU is intersection over union on copper pixels, accumulated over the whole set. The UNet doubles the better baseline on the owner split and holds most of that on the held out boards, with precision 0.36 and recall 0.29 there. The front layer is easier than the back on every model (UNet 0.23 against 0.14 IoU held out), which matches the data: back copper on these boards is mostly ground return and short jumpers, and the model sees only the pads. LightGBM is a useful control. At the default threshold it reaches recall 0.89 with precision 0.04, which says that nearly all copper lies in a predictable band around the pads but the band is far wider than the trace. Its most important feature by a factor of three is distance to the net's pad bounding box. The gap between the random and owner splits is small for the two baselines (0.136 against 0.129 for LightGBM), as expected for models that see nine local numbers per pixel and cannot memorise a board. The UNet sees the whole board, so that is where the leakage gap should appear; the random split run is in progress and the number goes into the final report.

The examples show what the numbers mean. Short nets between nearby pads are predicted well, including the layer. Long nets that cross the board are where the model gives up, because at pixel level there are many valid paths and the training signal for any one of them is weak. That is why the project does not stop at the prediction. The plan for evaluation has two levels. At the pixel level, the three models are compared on IoU, F1, precision and recall under both splits and on the held out boards, as above, with 256 by 256 runs and an ablation on the net attribute channels described below. At the routing level, which is the one that matters, the prediction becomes a per cell cost for a grid maze router, and the guided router is compared with the same router unguided and with Freerouting on the 97 clean test boards, on completion rate, total wire length, via count and design rule violations after zone refill. PCBWorld's published numbers on the same boards are the reference point.

## 5. Related Work and Novelty

PCBWorld (LG AI Research, 2026) is the closest system. It trains a transformer policy with PPO inside KiCad on 10,000 synthetic two layer boards and evaluates zero shot on real PCBench boards, passing 86 percent of the 99 easy boards cleanly against Freerouting's 80 percent, but only 45 percent of the medium boards against Freerouting's 78 percent. The authors never train on human copper. Learned Copper takes their test lists, their metrics and their Freerouting baseline, and supplies the signal they left out. Jain and Okabe (2017) trained a fully convolutional network to emit copper per pixel per layer from pin locations, on 50,000 synthetic chip samples, which is the direct ancestor of the UNet here; the difference is real boards and a per net formulation with the rest of the board as context. HubRouter (Du et al., NeurIPS 2023) showed that routes generated as images break connectivity and added a second stage that connects the pins; this project's router guidance step plays the same repair role with a classical router instead of a learned connector, which is cheaper and easier to trust.

The novelty is in two places. No published system trains a copper model on thousands of real, human routed boards; the academic routers use synthetic grids or router labelled data, and the industrial ones (DeepPCB, Quilter, Flux) publish neither papers nor data. And no published PCB routing result measures leakage: the owner split against random split comparison, with repository grouped splits frozen in a public file, is a contribution on its own, since it is the protocol the field will need whichever model wins. Beyond replication, the planned net attribute channels (net class width, power versus signal, differential pair membership) give the model the electrical context a human router has, and the guided versus unguided router comparison on a public test set is the experiment the related papers set up and did not run.

## 6. Progress and Remaining Plan

Completed since the proposal: the KiCad 10 toolchain with the design rule checker, the DSN export and import path and Freerouting in headless mode, all scripted; the dataset survey and the switch of source; the frozen test set and exclusion lists; the inventory, design rule filter and tiering of all 1,157 boards; geometry extraction and per net rasterisation of 645 boards; a related work survey of 123 references; the training and evaluation code; two baselines and the UNet trained and scored under both split protocols and on the held out boards.

The main challenges were in the data, and each cost about a day. The clearance violations were stale zone fills, found by looking at which rule types dominated. The test list hashes did not match any local file until I noticed the upstream files use Windows line endings. KiCad's DSN export hangs on a hidden dialog inside a long process, so each export runs in its own subprocess with a timeout. Compute is the laptop and free cloud sessions, which is why the midway numbers are at 128 by 128.

Remaining work, by week:

* Weeks 11 and 12: 256 by 256 training on a free cloud GPU; net attribute channels; ablation with and without them; the UNet random split number for the leakage table.
* Weeks 12 and 13: the grid maze router with the prediction as a per cell cost; Freerouting baseline on the 97 clean test boards under the same KiCad 10 check; guided versus unguided results on completion, wire length, vias and violations.
* Week 14: error analysis by net kind and board size; owner against random split on the routing metrics.
* Weeks 15 and 16: project presentation and final report; release of the splits, the model and the result files.

The risk to name is that the model predicts plausible copper that a router cannot realise. The guidance experiment is the only test of that, and a tie with the unguided router would still be reported as the finding, with the pixel results and the dataset as the contribution.
